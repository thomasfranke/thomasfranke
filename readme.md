### Featured Open Source

🔹 [**Flutter Clean Architecture + Riverpod**](https://github.com/thomasfranke/flutter-clean-arch-riverpod) *(Mobile)*  
  - My reference implementation of Clean Architecture + DDD in Flutter — a robust, test-focused structure for scalable applications.
  - **Four levels of tests** — unit, widget, narrow integration and on-device E2E against the live Binance API — reaching **100% line coverage**, with the scope and limits of each level documented rather than assumed.
  - 🔧 **Tech Used:** `Riverpod`, `AutoRoute`, `Dio`, `SharedPreferences`, `Freezed`, `dartz` (`Either`-based failures), `Mocktail`

🔹 [**TOM — Team-Oriented Markdown**](https://github.com/thomasfranke/tom) *(Mobile/Desktop · pre-alpha, built in public)*  
  - Taking scalable apps to the next level, this project uses a layered (n-tier) architecture with strong focus on architecture and testing
  - Architecture-first by design with totally independent layers: domain, core, presentation and, yes, desktop and mobile. All totally isolated, with a strong focus on testing and architecture.
  - **Spec-driven development:** heavy upfront investment in product specs and technical documentation establishing patterns and standards, written to guide both human contributors and AI coding agents consistently
  - Bringing 10+ years of technical documentation experience together with AI — a combination enabling productivity and applications that felt unimaginable just a few years ago
  - A Git client built for documentation instead of code: **rendered markdown diffs**, branching without ceremony, section blame, assisted conflict resolution. Local-first, MIT, no proprietary format.

🔹 [**Clean Architecture vs. Spaghetti Code in Flutter**](https://github.com/thomasfranke/flutter-clean-vs-spaghetti) *(Mobile · undergraduate thesis, graded with distinction)*  
  - This is my undergraduate thesis (Systems Analysis and Development), where I've built two apps with **identical features and identical dependencies**, but with opposite architectures.
  - Measured instead of argued: static analysis, import coupling, cyclomatic complexity and testability.
  - Check out my presentation (PT and EN) and the complete article (PT only, sorry)

🔹 [**TomLog**](https://github.com/thomasfranke/tomlog) *(Package · not yet published)*  
  - Dart logging library: categorized and color-coded logs, automatic file/class capture, bounded history, JSON export and hooks for monitoring systems.
  - 🔧 **Tech Used:** Dart
